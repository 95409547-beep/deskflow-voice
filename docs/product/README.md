## 首版范围

| 能力 | 当前事实 | 首版安排 |
|---|---|---|
| Mac → Windows | 当前两台设备的真实语音输入与松开停止已通过 | 正式产品化，补普通麦克风来源及干净安装验证 |
| Windows → Windows | 尚无实现与真人验收证据 | 首版必须新增发送端并完成端到端验收 |
| Windows → Mac | 尚未实现 Mac 语音接收端 | 后续版本 |
| Mac 连接 Siri 遥控器 → Windows | 现有链路已验证，依赖专用收音栈 | 首版重点设备兼容项，独立增强模块与安装引导 |
| Windows 直接连接 Siri 遥控器收音 | 尚未验证 | 不作为 Windows → Windows 基础能力的前提，另立设备研发项 |
| 登录自启与管理器恢复 | 当前两台设备已配置并做过恢复检查 | 改成通用安装器管理；必须补整机重启验收 |

Windows → Windows 首版基础来源为发送端现有的普通系统麦克风，配合可配置的按住说话键。两条首版路径都必须通过，才能发布完整 V1；单路径预览版应明确标注范围。

## 开发前先处理的三项依赖

1. Deskflow 的相关代码为 GPL-2.0-only（含相应例外），SiriRemoteForge 为 GPLv3 或更新版本，不能默认直接合并源码；组件组合与分发关系需先审查。
2. Siri 遥控器当前收音依赖 PacketLogger 与专用采集组件。PacketLogger 的获取和分发授权需单独处理，不能承诺所有依赖都已可放进一个安装包。
3. 当前豆包唤起使用版本相关的内部接口。首版需要明确兼容清单、更新检测和失败停用机制，不能宣称所有豆包版本均兼容。

具体裁定、责任与回退方式见[依据与决策记录](依据与决策记录.md)。这些是产品化工作项，未被写成已经解决的问题。
