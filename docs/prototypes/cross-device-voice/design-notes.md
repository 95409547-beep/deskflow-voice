# 界面设计说明 v0.2

## 日常先能用，设置按需出现

保持 Deskflow 首选项的整体风格，把语音内部拆成“使用 / 设备 / 设置”三页。首页只留开启状态、当前电脑方向、一条按住说话提示和主要操作，去掉重复解释、组件清单和设置按钮堆叠。

可点击入口：[index.html](index.html)。网页是交互原型，尚未接入原生 Qt 或真实语音服务。

| 页面 | 默认内容 | 进入时机 |
|---|---|---|
| 使用 | 状态、说话提示、开始/试用；异常时显示具体问题 | 日常入口 |
| 设备 | 角色、电脑、声源、接收依赖 | 更换设备或排障 |
| 设置 | 按键、自启；更多选项中放诊断和完整向导 | 用户主动调整 |

## 一次开始，按需补齐

“开始使用”默认选系统麦克风，已确认的设备与已具备的权限不再重复询问。需要时才停在当前一步：

1. 未配对：显示对端和确认码，用户确认后继续。
2. 来源未就绪：请求麦克风权限或检查指定来源；不悄悄切换用户选中的声源。
3. 准备完成：直接试说一句，确认出字与松开停止后回到首页。

接收端不额外要求设置发送按键或本机声音来源。完整五步向导仍在设置页“更多选项”里，日常路径不强制经过。权限、确认码及组件安装在正式实现中仍需真实系统结果，原型按钮不能替代这些结果。

## 支持方向与来源

Mac 发送到 Windows；Windows 在设备页切换发送/接收，发送目标仍是另一台 Windows。Mac 接收首版不可选。角色服务检测尚未接入，原型按所选设备视角提供默认用途。

普通麦克风是默认来源。Mac 的 Siri 来源需单独确认系统配对、专用收音组件及 PacketLogger；更换来源会撤销原先检查。Windows 的 F8 与 Mac 的右 Option 是演示设置，正式产品仍需原生录键及冲突检查。

## 异常才展开说明

- 离线：显示等待对端，给连接处理入口，恢复后重新按下。
- 来源未检查或不可用：提供来源检查或更换入口。
- Windows 接收组件缺失：提供官方安装步骤，再返回检测。
- 豆包版本不兼容：保留阻断和兼容说明，不能一键假定兼容。

测试弹窗默认折叠检测过程，先显示按住按钮与输入结果；需要定位问题时再展开。诊断和详细组件信息不占首页。漏松键自动恢复属于键鼠内核，本次不增加防粘键设置开关。

## 真实服务接入

界面状态后续绑定身份、权限、来源、输入法和会话服务，不能沿用原型布尔值。接收端每次新按下绑定当前输入位置，不登记应用。输入位置变化、锁屏、断线等由服务结束本轮，界面反映真实结果。

开启状态即时响应，设备和偏好更改仍可保存/取消。登录准备后续由平台生命周期组件实现。正式 Qt 布局需要适配首选项窗口尺寸，浏览器截图不承诺跨平台像素一致。
